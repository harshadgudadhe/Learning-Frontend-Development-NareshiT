Asynchronous:
------------- 
    Synchronous:
            JavaScript is normally synchronous and single-threaded language. 
            synchronous executes code one after other and single threaded means execute only one code at a time.
        Example(synchronous):
            console.log("Hii");
            console.log("bye");
            Here,
            first method will execute first then after only the next method will execute.

    Asynchronous:
            JavaScript(AJAX) allows to execute code , not Immediately.
            to execute only specific code with interrupting other codes(UI).
            example:
                    adding item to cart or score update in cricbuzz etc.

            we can use browser default timers to understand AJAX. Browser provides two default methods called:
            1. setTimeOut, clearTimeOut
            2. setInterval, clearInterval

    1.  setTimeOut: used to perform a task after a specific time 
        setTimeOut(callback function, time in milisecond)
        eg. 
           setTimeOut(()=> console.log("hello wprld"),1000);
           It prints hellow world after 1sec.
           In case if any other code is next to it, it will get executed Immediately.

    2.  setInterval(): used to perform a task every time of specific interval 
        setInterval(callback function, time in milisecond);
        eg:
           setInterval(()=> console.log("hello world"),1000);
           it prints hellow after every 1sec untill it stop Explicitly .

        We can stop these methods using clearTimeOut & clearInterval methods.
        eg.
           
    Prerequisites to understand AJAX: 
        1. good understanding of callbacks 
        2. good understanding of event loop

                                        /* callback hell , promises */

Callback-hell: 
            callbacks creates a problem called "callback hell" or "pyramid of doom", which is nothing but nested callback multiple times(one within another).
            callback hell code is difficult to understand or maintain. 
            To avoid this problem, we can use "promises".

Promises: 
---------
        An object which describes an eventual completion of Asynchronous operation/task.
        It contains three states : 
               ->pending (it's defualt-state)
               ->fulfilled
               ->rejected

    Eg:
       "I will give you money tommorow" is a promise.
       It's Asynchronous operation because it's not completing Immediately this promise contain three states:
            -> "fullfield": really gave the money. 
            -> "rejected": not gave you money.
            -> "pending": keep you waiting.

        A promise can be handled using then and catch promise
        .then(callback)
        .catch(callback)

APIs:
-----
    used to communicate between two softwares(client and server).
    client requests to the server using API and server responds to the client using API.
    APIs are created and maintained by server.

    client receives a promise whenever it requests to the API, once the promise resolved, it receives the data through API.
